Why trim

Every skill you load is paid for in context.

Skills grow by accretion. Someone adds a caveat, an example, a "please always remember". Nobody removes anything. Six months later your agent reads 3,000 tokens to learn how to run a linter.

Context is a budget

Thirty skills at 3k tokens each is 90k tokens spent before the user types a word. Trimmed skills leave room for the actual task.

Padding hides the instruction

Hedges, pleasantries and restated warnings dilute the one line that matters. Models follow crisp imperatives better than paragraphs of reassurance.

Bloat compounds

Verbose skills trigger less reliably and cost more every single run. The cost is small per call and enormous per month.

How it works

Scan. Trim. Verify. Ship.

Four passes, one command. Nothing ships unless the trimmed skill matches the original on its own evals.

  1. 01

    Scan

    Parse SKILL.md and every referenced file. Map each instruction, example and link to how often it actually influences a run.

  2. 02

    Trim

    Remove dead instructions, collapse duplicates, compress examples to the smallest version that still teaches, and rewrite hedges into imperatives.

  3. 03

    Verify

    Run the skill's evals against both versions. The trim is accepted only when it matches or beats the original on every case.

  4. 04

    Ship

    Open a pull request with a readable diff, a token report and the eval results. You review the cut like any other change.

Features

Everything a careful editor would do, in seconds.

Dead-instruction detection

Finds rules that never change an outcome across your eval set and flags them for removal.

Redundancy collapse

Merges the same warning stated four ways into one line, kept where the model needs it most.

Example compression

Shrinks worked examples to the shortest form that still demonstrates the pattern.

Hedge removal

"Please make sure you always try to" becomes a verb. Politeness costs tokens and buys nothing.

Token budgets

Set a ceiling per skill or per repo. CI fails when a skill grows past it, before the bloat compounds.

Behavior-preserving verification

Every trim is checked against your evals. No parity, no merge. Regressions never ship silently.

Diffs you can read

Each cut is annotated with the reason: dead, duplicate, hedge, or compressed. Accept or reject line by line.

Works where your skills live

Claude Code, Codex, Cursor, or a plain folder of Markdown. If it's a SKILL.md, it trims.

    FAQ
    
          
    Questions, trimmed.
    
        
    
        
    
          
    
            Will trimming change how my skill behaves?
            
    Not without you knowing. Every trim is run against the skill's evals. If any case regresses, the trim is rejected and the report shows which cut caused it. You can also accept or reject individual cuts in the diff.
    
          
    
          
    
            What counts as a "skill"?
            
    Any folder with a SKILL.md (plus optional references, scripts and examples). That covers Claude Code skills, Codex and Cursor instructions, and plain Markdown prompt libraries.
    
          
    
          
    
            Does my skill content leave my machine?
            
    On the free CLI, no. Scanning, trimming and verification all run locally. Hosted verification on Pro and Team sends skill text to our runners; it's encrypted in transit and deleted after the run.
    
          
    
          
    
            I don't have evals yet. Can I still use it?
            
    Yes. Run circumskill evals init to scaffold a starter set from your skill's examples and trigger phrases. Trims without evals are marked "unverified" in the report so you can review them by hand.
    
          
    
          
    
            Can I undo a trim?
            
    Trims are plain diffs. Revert the commit or reject the pull request. Circumskill also keeps the original alongside the trim until you merge.
    
          
    
          
    
            Why the name?
            
    Because it cuts around the skill and removes only what isn't needed. We considered gentler names. None of them were as memorable.
